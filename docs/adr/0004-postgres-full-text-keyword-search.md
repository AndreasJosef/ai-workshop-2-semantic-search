# Postgres full-text search (generated `tsvector` column) as the keyword mode

The keyword-vs-semantic comparison (issue 06) needs a lexical search path alongside the two embedding RPCs. The corpus already lives in Postgres/Supabase, and the comparison tool and UI consume one `SearchMatch` shape from one RPC-per-mode pattern (`match_documents_768` / `match_documents_3072`), so a third mode should be a third RPC of the same shape — not a parallel stack.

We use vanilla Postgres full-text search: a `content_tsv tsvector` column **generated** from `content`, a GIN index over it, and a `match_documents_keyword(query_text, match_count)` RPC ranked by `ts_rank(content_tsv, websearch_to_tsquery('english', query_text))`. The RPC filters with `content_tsv @@ websearch_to_tsquery('english', query_text)` so that chunks with zero lexical relevance never enter the ranking (non-matches would score 0 anyway); a consequence is that `websearch_to_tsquery`'s AND semantics mean a query whose *any* content word is absent from the corpus returns no rows at all — accepted here, since surfacing that behavior is part of the comparison. The column is generated (not written by the app), so the existing corpus/kb ingestion pipeline needs no changes and existing rows back-fill automatically. `websearch_to_tsquery` is used instead of `plainto_tsquery`/`to_tsquery` so free-text typed into the same search box — including quoted phrases, `OR`, and `-exclusion` — parses without ever erroring on malformed boolean syntax. The RPC's output column is named `score` (and `SearchMatch.similarity` was renamed to `SearchMatch.score`) because `ts_rank` is not a cosine similarity and is on a different scale.

Considered and rejected: an external search engine (new infrastructure, out of scope for a comparison exercise); `pg_trgm` fuzzy matching (add-on extension beyond vanilla Postgres, and trigram similarity is not the lexical model we want to compare against); app-side `LIKE '%q%'` filtering (no relevance ranking, no index support); populating the `tsvector` from the application (would require touching `src/kb/store.ts` for no benefit over a generated column).
